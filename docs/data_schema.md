# 기업 데이터 스키마와 출처 규칙

> big-patch 1단계에서 정리했다. 원칙: **실제 기업에 대해 사실이 아닌 정보는 한 글자도 두지 않는다.**
> 스크래핑은 하지 않는다. 데이터는 ① 공식 API ② 팀이 공개 자료에서 확인해 출처와 함께 넣은 값 ③ 이름까지 가상인 예시 데이터, 세 가지뿐이다.

## 1. 데이터 종류 (`data_kind`)

| 종류 | 어디에 | 기업명 | 별점·리뷰·면접 질문 등 | 화면 표시 |
|---|---|---|---|---|
| `sample` 가상 예시 | `data/company_showcase.py` (20곳) | **가상** | 팀이 만든 예시 (사실 아님) | "가상 기업 · 예시 데이터" 칩 + 예시 데이터 안내 |
| `verified` 실제 기업 | `data/curated_companies.json` (관리자 화면 · 스크립트로 입력) | 실제 | **없음** (스키마에서 금지) | "출처 확인 · 수집일" 칩 + 출처 링크 |
| 채용공고 백업 | `data/companies.py`, `data/backup_master.json` | **가상** (공기업 10곳 포함) | 예시 공고. 확인 못 하는 채용 조언(`ai_tip`)은 비움 | BACKUP DATA 배지 |
| 공식 API 실데이터 | Q-Net · 고용24 (키가 있을 때) | 실제 | API 응답 그대로 | LIVE API 배지 |

`data.company_showcase.all_companies()` 가 가상 20곳과 실제 기업을 합친다.
같은 id 가 있으면 실제 기업 레코드로 **통째로 바꾼다**(합치지 않는다). 예전에는 덮어쓰기 방식이라
실제 기업이 가상 기업의 별점·장단점·면접 질문을 물려받을 수 있었다.

## 2. 실제 기업 레코드 스키마 (`services/curated.py` 의 `FIELDS`)

| 키 | 뜻 | 필수 | 규칙 |
|---|---|---|---|
| `id` | 식별자 | ✔ | 영문·숫자·밑줄. 찜·열람 기록이 이 키로 연결되므로 바꾸지 않는다 |
| `name` | 공식 명칭 | ✔ | |
| `size_tag` | 기업 유형 | ✔ | 대기업 · 중견기업 · 중소기업 · 강소기업 · 공기업 · 스타트업 |
| `category` | 계열 | ✔ | 기계 · 전자/전기 · IT/정보통신 · 바이오/화학 · 농생명 · 해양 · 건축/토목 |
| `field_tag` | 분야 태그 | | 비우면 계열과 같게 |
| `description` | 업종 한 줄 | ✔ | 사업 내용 요약 (공개 자료 기준) |
| `region` | 소재지 | | 본사·사업장 소재지. 모르면 비움 |
| `official_recruit_url` | 공식 채용 페이지 | | http(s) |
| `hire_dept` | 채용 직무 | | 공식 채용공고에 있을 때만 |
| `work_conditions` | 근무 조건 | | 공식 채용공고에 있을 때만 |
| `required_certs` | 우대·필수 자격증 | | 공식 채용공고 기준 |
| `required_skills` | 요구 역량 | | 공식 채용공고 기준 |
| `ideal_talent` | 인재상 키워드 | | 짧은 키워드로 요약 |
| `talent_summary` | 인재상 한 줄 요약 | | **80자 이내, 원문 복사 금지** |
| `talent_source_url` | 인재상 출처 | 인재상을 쓰면 ✔ | http(s) |
| `source_url` | 레코드 출처 | ✔ | http(s) |
| `source_type` | 출처 유형 | ✔ | 공식 홈페이지 · 채용 공고 · 보도자료 · 공공데이터 · 기타 |
| `checked_by` | 조사자 | ✔ | |
| `checked_at` | 수집일 | ✔ | YYYY-MM-DD, 오늘보다 뒤일 수 없음 |

**금지 항목** (`FORBIDDEN_REAL_FIELDS`): `overall_rating`, `ratings`, `pros`, `cons`, `interview_questions`,
`avg_applicant_grade`, `avg_applicant_certs`, `benefit_short`, `exam_keywords`, `salary`, `reviews`.
실제 기업에 대해 팀이 확인할 수 없어 지어내게 되는 값이다. 저장할 때는 검증에서 막고,
예전 형식으로 저장된 값이 있어도 읽을 때 `sanitize_real()` 이 지운다.

## 3. 갱신 절차

1. 공식 홈페이지 · 공식 채용공고 · 공공데이터에서 사실을 확인한다. 확실하지 않은 칸은 비운다.
2. 관리자 화면 '기업 데이터 입력' 또는 스프레드시트(CSV)로 입력한다.
3. 검사: `python scripts/update_company_data.py --report`
   - CSV 들여오기: `python scripts/update_company_data.py --import 조사.csv` (규칙을 통과한 행만 반영)
   - 예전 형식 정리: `python scripts/update_company_data.py --fix`
   - 수집한 지 180일이 지난 레코드는 "재확인 필요"로 표시된다.
4. `data/curated_companies.json` 을 커밋한다 (Streamlit Cloud 는 재배포 때 파일이 초기화된다).

## 4. 공식 API

| 데이터 | API | 키 (secrets) | 키가 없거나 실패하면 |
|---|---|---|---|
| 자격증 목록 | 공공데이터포털 Q-Net | `QNET_API_KEY` | `data/certifications.py` 45종 (BACKUP) |
| 채용공고 | 고용24 Open API | `WORKNET_API_KEY` | 가상 채용공고 34건 (BACKUP) |
| 공공기관 채용 | 잡알리오 · 공공데이터포털 (규격 확인 전) | `services/api_registry.py` | 가상 공공기관 10건 (BACKUP) |
| 강소기업 | 규격 확인 전 | `services/api_registry.py` | 가상 강소기업 10건 (BACKUP) |

규격(엔드포인트·응답 형식)을 활용가이드로 확인하기 전에는 추측으로 클라이언트를 만들지 않는다.
