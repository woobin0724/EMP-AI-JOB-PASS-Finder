# 회귀 검증 절차

배포 전에 이 순서대로 돌립니다. 앞 단계가 실패하면 뒤 단계는 의미가 없습니다.

```bash
python3 scripts/check_static.py                 # 0단계 — 정적 검사 (수 초)
streamlit run app.py --server.port 8501 &       # 앱 실행
python3 docs/qa_mobile.py                       # 1단계 — 모바일 QA 측정
```

## 0단계 — 정적 검사 (`scripts/check_static.py`)

Streamlit 화면 코드는 **import 가 하나만 빠져도 그 화면이 통째로 트레이스백**이
됩니다. 그런데 이건 해당 화면을 실제로 렌더링해봐야 드러나고, `py_compile` 은
문법만 보므로 잡지 못합니다. 실제로 이 저장소에서 `ui.theme` 의 `GOLD`·`BRAND`,
`ui.components` 의 `render_html` 을 이렇게 두 번 놓쳤습니다.

`pyflakes` 는 정의되지 않은 이름을 소스만 읽고 찾아줍니다. 브라우저를 띄우는
1단계보다 훨씬 빠르므로 맨 앞에 둡니다.

| 판정 | 항목 | 이유 |
|---|---|---|
| **FAIL** | 문법 오류 · 정의되지 않은 이름 · import 실패 | 런타임에 앱을 깨뜨린다 |
| WARN | 미사용 import · 빈 f-string | 동작에는 지장 없음 |

미사용 import 까지 FAIL 로 잡으면 경고가 쌓여 아무도 안 보게 되므로 나눠 두었습니다.
현재 기준선은 **FAIL 0 · WARN 0** 이므로, 경고가 생기면 그 커밋에서 생긴 것입니다.

종료 코드는 통과 0 / 실패 1 이라 CI 나 pre-commit 훅에 그대로 물릴 수 있습니다.

설치: `pip install pyflakes` (requirements-dev.txt 에 포함)

## 1단계 — 모바일 QA (`docs/qa_mobile.py`)

QR 코드로 스캔해 폰으로 접속했을 때 전체 플로우가 깨지지 않는지 확인합니다.
눈으로 훑는 대신 **브라우저에서 실제로 측정**합니다.

9개 화면 × 2개 기기(모바일 390×844 / 데스크톱 1440×950) = 18개 조합을 자동으로 돌며
아래 항목을 재고, 화면별 스크린샷을 남깁니다.

---

## 자동 측정 항목

| # | 항목 | 합격 기준 | 왜 중요한가 |
|---|---|---|---|
| 1 | 가로 스크롤 | `scrollWidth == viewportWidth` | 가로로 밀리면 학생이 좌우로 스와이프해야 하고 레이아웃이 깨져 보인다 |
| 2 | 뷰포트 이탈 요소 | 0개 | 카드·표가 화면 오른쪽을 뚫고 나가면 내용이 잘린다 |
| 3 | 터치 타깃 | 버튼 높이 ≥ 44px (모바일) | 애플 HIG 권장치. 엄지로 누르기 어려우면 오조작이 난다 |
| 4 | 입력창 폰트 | ≥ 16px (모바일) | **16px 미만이면 iOS 사파리가 포커스 시 화면을 확대**하고, 그 확대가 풀리지 않아 이후 레이아웃이 어긋난 채로 남는다 |
| 5 | 본문 가독성 | 11px 미만 텍스트 확인 | 캡션이라도 폰에서 11px 아래는 읽기 어렵다 |

측정 대상에서 제외하는 것과 그 이유:
- **Streamlit 개발 툴바**(Deploy / 메인메뉴 버튼) — 배포본 사용자에게 보이지 않는다
- **컨트롤 내부 서브요소**(드롭다운 화살표, 비밀번호 표시 토글) — 독립 탭 타깃이 아니다.
  컨트롤 아무 곳이나 누르면 동작하므로, **감싸는 컨트롤이 44px 이상이면 통과**로 본다
- **터치 타깃·입력 폰트 기준은 모바일에만 적용** — 마우스로 쓰는 데스크톱에 같은 잣대를
  대면 잘못된 실패가 나온다

## 손으로 확인할 항목 (자동 측정으로 못 잡는 것)

실제 폰에서 QR로 접속해 아래를 훑어주세요.

- [ ] **랜딩 → 로그인 → 역할 선택 → (반 등록) → 허브 → 기능 화면** 전 구간 이동
- [ ] 상단 내비가 가로로 스크롤되는가 (세로로 쌓이면 화면을 다 먹는다)
- [ ] 카드가 **세로로 쌓이는 순서**가 맞는가 (학생 명단·기업 목록의 순서가 뒤바뀌지 않는지)
- [ ] 마스코트가 배경 네모 없이 깔끔하게 뜨는가
- [ ] 입력창을 탭했을 때 화면이 확대되지 않는가 (iOS 사파리)
- [ ] 자소서 생성 후 결과 텍스트 영역을 스크롤할 수 있는가
- [ ] 선생님 계정: 반 코드가 잘리지 않고 전부 보이는가 (복사 버튼 동작)
- [ ] 새로고침했을 때 보던 화면이 유지되는가 (URL 동기화)
- [ ] 사파리·크롬 양쪽에서 동일한가

## 기준선 (최종 측정 결과)

18개 조합 **전부 통과**. 이 과정에서 발견해 고친 실제 결함:

| 발견 | 조치 |
|---|---|
| selectbox·multiselect 입력이 14px → iOS 자동 확대 | BaseWeb 내부 input 까지 덮도록 선택자 확장 |
| `.stButton` 클래스 선택자가 일부 버튼을 놓쳐 40px로 남음 | `data-testid` 기반 선택자로 교체 |
| selectbox 38px · 비밀번호 입력 래퍼 40px | 모바일에서 컨트롤 최소 높이 44px |
| 자소서 배지 카드의 **원시 HTML이 텍스트로 노출** | markdown 이 4칸 이상 들여쓴 줄을 코드 블록으로 해석 → 들여쓰기 제거 |
| `st.markdown('<div class="mjp-card">')` 가 **빈 박스만 렌더링** (5곳) | Streamlit 은 markdown 호출마다 독립 DOM 을 만들어 위젯을 감싸지 못한다 → 제거 |
| multiselect placeholder 가 영문 "Choose options" | 한국어로 지정 |
